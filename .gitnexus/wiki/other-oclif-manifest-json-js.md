# `oclif.manifest.json.js`

## Overview

This module is the OCLIF CLI manifest loader. It reads the generated `oclif.manifest.json` file and exports its contents as a JavaScript object, making the CLI command metadata available to the OCLIF framework at runtime.

## Purpose

OCLIF (Open CLI Framework) generates a manifest file (`oclif.manifest.json`) containing metadata about all available commands, their arguments, flags, and descriptions. This module serves as the bridge between the static JSON manifest and the runtime JavaScript code by:

1. Locating the manifest file relative to this module's directory
2. Reading the JSON content from disk
3. Parsing and exporting the manifest for consumption by OCLIF

## How It Works

```javascript
// Resolve the directory of this module using ES module conventions
const __dirname = path.dirname(fileURLToPath(import.meta.url));

// Build the path to oclif.manifest.json in the same directory
const manifestPath = path.join(__dirname, 'oclif.manifest.json');

// Read and parse the JSON file, export as default
export default JSON.parse(fs.readFileSync(manifestPath, 'utf8'));
```

### Path Resolution

The module uses `fileURLToPath(import.meta.url)` to convert the ES module URL to a filesystem path. This is necessary because:
- `import.meta.url` provides a `file://` URL, not a filesystem path
- `path.dirname()` requires a string path, not a URL
- This pattern is the standard way to get `__dirname` in ES modules (since `__dirname` is not available in ESM)

### Manifest Loading

The manifest is loaded synchronously using `fs.readFileSync()`. This happens at module import time, meaning the manifest is available immediately when this module is imported elsewhere.

## Generated Manifest

The `oclif.manifest.json` file is generated by running:

```bash
oclif manifest
```

This command scans your CLI's command files and produces a JSON file containing:
- Command names and descriptions
- Arguments and flags for each command
- Aliases and version information

## Usage in OCLIF

When OCLIF initializes, it imports this module to access command metadata without needing to parse source files at runtime. This improves startup performance.

```javascript
import manifest from './oclif.manifest.json.js';
```

## File Relationship

```
oclif.manifest.json.js  →  reads  →  oclif.manifest.json
       ↓
   (exports parsed JSON)
```

## Considerations

- **Synchronous loading**: The manifest is read synchronously. For most CLIs, this overhead is negligible since the manifest is typically small (< 100KB).
- **Build-time requirement**: The manifest must be generated before distribution. Typically this is handled in the CI/CD pipeline or as part of the npm `prepack` script.
- **ES Modules only**: This module uses ES module syntax (`import`/`export`) and is designed for modern Node.js environments.
